# Лабораторная работа №2 — вариант 3

Цель: освоить модульное тестирование Java-класса с помощью JUnit 4.

## Что требовалось

Реализовать класс «Строка» с полями: длина, массив символов и язык.
Предусмотреть установку и считывание длины и языка, добавление данных другой
строки и автоматический пересчёт длины. Написать модульные тесты JUnit 4.
Ошибочные аргументы обрабатывать через исключения Java.

## Что сделано

В `TextLine` три закрытых поля: `length`, `characters`, `language`.
Конструктор принимает текст и язык, превращает текст в массив символов
и вычисляет длину. Название `TextLine` выбрано, чтобы не путать класс
со стандартным `String` в Java.

- `getLength()` и `getLanguage()` возвращают длину и язык.
- `setLanguage()` меняет язык.
- `setLength()` меняет размер массива: при уменьшении отбрасывает конец,
  при увеличении дополняет его нулевыми символами `\0`.
- `append()` дописывает символы другой строки и пересчитывает длину.

У массива символов нет геттера и сеттера. При добавлении другой строки
язык исходной строки сохраняется; в условии не указан способ объединения языков.
Пустой текст разрешён. Отрицательная длина, `null` вместо текста или
добавляемого объекта, а также отсутствующий или пустой язык вызывают
`IllegalArgumentException`. Эти правила для ошибочных аргументов выбраны
для реализации, поскольку задание не перечисляет их отдельно.

## Тестирование

`TextLineTest` содержит 14 тестов: создание объекта, пустая строка,
изменение языка, уменьшение и увеличение длины, нулевая и отрицательная
длина, объединение строк, пустые строки, добавление строки к самой себе
и ошибочные аргументы. Проверяются как значения полей, так и содержимое
массива. Для проверки закрытого массива только в тестах используется
рефлексия — получение поля по имени; в самом классе она не нужна.

Использованы эквивалентное разделение (корректные и ошибочные аргументы),
граничные значения (пустая строка, длины 0 и -1) и предугадывание ошибки
(добавление строки к самой себе).

## Как запустить

Проверка выполнена: исходники скомпилированы компилятором Eclipse ECJ,
тесты запущены через JUnitCore из JUnit 4.13.2. Результат: `OK (14 tests)`.
Maven в среде выполнения отсутствовал, поэтому команда `mvn test`
здесь не запускалась.

Нужны JDK 8 или новее и Maven. Из папки проекта:

```sh
mvn test
```

В Eclipse можно импортировать проект через **File → Import → Maven →
Existing Maven Projects**, затем выбрать `TextLineTest` и выполнить
**Run As → JUnit Test**.

Отдельный `main` не добавлен: результат работы по заданию — тестируемый
класс и набор модульных тестов к нему.
